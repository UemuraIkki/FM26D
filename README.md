# FM26D — サッカーリーグ観測シミュレーター

Football Manager 風のサッカー世界を「放置して観測する」ためのヘッドレスシミュレーター。
要件定義は [football-sim-requirements-v1.md](football-sim-requirements-v1.md) を参照。

## 現在の状態: フェーズA〜I 完了(要件定義書の全フェーズ実装済み)

- プレミアリーグ20クラブの日程生成(ダブルラウンドロビン、Berger法)
- ポゼッション連鎖マルコフ試合エンジン(1ティック≒7.5秒、統一ロジスティック成否判定)
- 全イベントログ(パス/ドリブル/シュート/タックル等)とイベント由来の選手採点
- 順位表(勝点→得失点差→総得点)
- 日次ティックのシーズンループ
- 完全決定論(単一シードから全乱数を導出。同一シード=同一の歴史)
- ロール適性スコア(20ロール、重みベクトルは `data/roles.json` でデータ駆動)
- デプスチャート: ロール別1st/2nd/3rd格付け、不足(補強需要)と余剰(放出候補)の機械検出
- スタメンはロール適性でスロットごとに選考
- 契約(賃金・年数)、市場価値関数 `base(ability)×ageCurve×contractFactor×leagueCoef`、契約満了→フリー移籍
- 移籍ウィンドウ(夏7-8月・冬1月): 需要スキャン(スタメン強化+控え補充)→費用対効果でターゲット選定(他クラブの登録選手にはプレミア価格で打診)→クラブ間交渉(自己評価×デプス係数)→**選手本人の判断**→成立
- 選手本人の判断(フェーズD): 予想出場時間(移籍先デプスチャートでの地位)・賃金・クラブ評判を野心属性で重み付けして受諾/拒否。**出場機会を理由とした移籍拒否(PLAYING_TIME)が観測される**(完了条件)。同一窓内の再打診はクールダウン
- 財務: 月次賃金・チケット収入・放映権(固定+順位賞金)。全取引を複式Ledgerに記録し、**金銭保存則をテストで検証**(ドリフト0)
- モラル(フェーズE): 選手ごとに morale/出場満足度/監督信頼、クラブごとにチーム雰囲気。日次平均回帰+イベント変動(勝敗・連続ベンチ外・移籍・契約更新)。試合能力への影響は**±5%にハードキャップ**し、10シーズン連続実行で非発散をテストで検証
- 役員会・監督(フェーズF): 監督は独立エンティティ(戦術・育成・名声、試合への影響±2%)。役員会は期待順位(戦力順)と実績の乖離+ロッカールームの信頼から信頼度を算出し、閾値で解任。解任された監督は市場に戻り、後任は市場の最有力者から招聘(監督自身が市場を移動)。**約8交代/シーズンの現実的な頻度**をテストで検証
- 複数リーグ+CL+影の世界(フェーズG): 5大リーグ(PL/ラ・リーガ/ブンデス/セリエA/リーグ・アン)を1つの日次ループで並行実行し、**リーグ間移籍が機能**(完了条件)。UEFAチャンピオンズリーグ(32チーム、8グループ+ノックアウト、域外は抽象クラブ)。影の世界(夏の新人供給+シーズン末の未契約自由選手退出)
- 代表戦+W杯/EURO(フェーズH): 国籍(重み付き procedural 割当)、フィットネス/怪我(0-100スケール、日次回復、試合後消費+怪我判定、±5%キャップ)、代表招集(ポジション別クオータ保証)、代表戦ウィンドウ(9/10/11/3月)、W杯(4人組32か国)/EURO(3人組24か国)を1つの汎用大会クラスで実装。**4年周期(startYear%4===2→WC/===0→EURO)で大会が完走**(完了条件)
- 成長・老化・引退・新人供給(要件4.3): 潜在能力への成長曲線(ピーク26歳、31歳超で衰退)、33歳から上昇する引退確率(40歳で確実)、クラブごとの毎季ユースアカデミー新人補充。長期健全性テスト(要件7必須、`npm run healthcheck`でCSV出力+閾値監視): リーグ平均年齢/能力ドリフト・優勝クラブのジニ係数(`src/stats/gini.ts`)・引退対新人供給バランス・金銭保存則を10シーズン自動実行で検証
- 観測UI(フェーズI): 統一ニュースフィード(移籍・監督交代・引退・優勝・初キャップ・出場100試合到達)、選手ウォッチリストとキャリア追跡(引退後もアーカイブ経由で継続)、SQLiteチェックポイント(シーズン粒度で決定論を完全保持、`node:sqlite`組み込みモジュール使用)、主要選手(通算100試合以上または代表歴あり)の永久保持+それ以外は引退5年後に詳細削除(要件6.4)

### キャリブレーション実績(1000シーズン / 380,000試合 — フェーズA完了条件)

| 指標 | 実測 | 目標 |
|---|---|---|
| 1試合平均得点 | 2.68 | 2.6-2.8 |
| パス成功率 | 84.1% | 78-85% |
| 1試合シュート数(チームあたり) | 12.1 | 11-14 |
| ホームアドバンテージ(勝率差) | +9.5% | +8-10% |

勝/分/敗 = 44.2% / 21.0% / 34.8%。実行速度は約0.15秒/シーズン(1000シーズンを154秒で完走。性能要件「1シーズン10分以内」に対し大幅な余裕)。

## 使い方

```bash
npm install
npm test                # 全テスト(決定論・日程・順位表・エンジン・大会・観測UI 等)
npm run season          # 1シーズン実行して順位表を表示
npm run season -- --seed 42
npm run calibrate -- --seasons 50   # キャリブレーション指標を検証
npm run depth                       # 全クラブの不足/余剰一覧
npm run depth -- --club ARS         # 1クラブのデプスチャート詳細
npm run healthcheck                 # 長期健全性テスト(10シーズン)をCSV出力+閾値監視

# 観測UI(フェーズI): 複数シーズンをSQLiteにチェックポイントしながら連続実行
npm run play -- --seed 1 --seasons 5 --db world.sqlite
npm run play -- --seasons 3 --db world.sqlite --resume   # 続きから再開
npm run feed -- --db world.sqlite --type TITLE            # ニュースフィード検索
npm run watch -- --db world.sqlite --player LIV-01         # 選手をウォッチ登録
npm run watchlist -- --db world.sqlite                      # ウォッチ中選手の状況一覧
npm run unwatch -- --db world.sqlite --player LIV-01
```

`play`のチェックポイントは**シーズン単位**の粒度(季中の日単位一時停止・再開はスコープ外 — 季をまたぐ一時オブジェクトを持たない`World`単体で決定論を完全保持できる粒度として採用)。

### 設計上の不変条件

- 乱数は必ず `src/core/rng.ts` の `Rng` を使う。`Math.random()` 禁止(決定論要件 3.2)
- サブシステムの乱数は `deriveRng(worldSeed, label)` で導出し、消費順序の影響を分離する
- `src/engine/` は独立パッケージ相当。sim 側の型を import しない(将来 Rust/WASM 置換可能)
- クラブの意思決定は必ず `ClubDecisionMaker` 経由(要件1の絶対制約)。観測モードは全クラブ `AIDecisionMaker`
- ワールドは `buildWorld` で一度だけ構築し、シーズンをまたいで永続。選手の所有権変更は `transferPlayer` のみ
- 決定的なソートのタイブレークは `compareIds`(ロケール非依存)を使う。`localeCompare` 禁止

### 既知の制約(記録)

- `Math.exp`/`Math.log`/`Math.cos` に依存するため、異なるランタイム(将来のRust/WASM)とはビット互換の決定論にならない。置換時に固定小数点または多項式近似で対処予定
- スタメン選考は希少度順の貪欲法(充足保証あり)。全体最適割り当てではない
